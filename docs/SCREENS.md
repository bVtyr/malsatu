# Карта экранов и пользовательские потоки

Все экраны доступны по `/{kk|ru}/…`, переключение языка — одна кнопка в шапке (сохраняется в cookie). Нижняя навигация: Главная · Поиск · **Подать** · Чаты · Профиль.

## 1. Карта экранов (web, MVP)

## 2. Потоки по ролям

### Гость
Главная → поиск/фильтры/карта → карточка → индекс цен. Действия, требующие аккаунта (звонок, чат, оффер, избранное, сохранённый поиск), ведут на `/login?next=…` и возвращают обратно.

### Покупатель (физлицо/организация)
1. Вход по телефону → имя/тип аккаунта.
2. Поиск → карточка → **позвонить** (подменный номер) / **написать** (чат с автопереводом) / **предложить цену**.
3. Оффер принят → кабинет → «Безопасная сделка» → оплата → отслеживание статусов → осмотр (24 ч) → подтверждение или спор с фото/видео → отзыв.
4. Сохранённые поиски → push/SMS о новых объявлениях. «Куплю» — публикация запроса из мастера (тип «Куплю»).
5. Согым: `/sogym` → выбрать сбор → ⅛/¼/½ → оплата → уведомление о наборе → доставка.
6. Осмотр ветеринаром: кнопка на карточке → назначение ветеринара района → отчёт в сделке.

### Продавец (физлицо/ИП/КХ/ТОО)
1. Мастер: фото с камеры (сжатие, водяной знак), голосовое описание, подсказка цены по региону, калькулятор выхода, бирки ИНЖ, ветдокументы, точка на карте (адрес скрыт).
2. Публикация: первые 3 объявления — премодерация; далее сразу активно; уведомление о решении модератора с причиной.
3. Кабинет: статистика по объявлению, офферы (принять/отклонить/встречное — из чата), бронь/продано/частичная продажа, продление, массовая загрузка CSV (API).
4. Сделка: «готовится» → «в пути» (или перевозчик) → выплата после подтверждения; споры — переписка с арбитром.
5. Шаблоны быстрых ответов; уведомления о запросах «Куплю» в своём регионе.

### Хозяйство/компания
Организация (`organizations`) с сотрудниками (`org_members`, роли owner/staff): общие объявления и сделки. В MVP — модель данных и RBAC; экраны управления сотрудниками — v2.

### Перевозчик
Профиль (тип транспорта, вместимость, регионы, документы) → `/transport`: открытые заявки → отклик с ценой → выбран заказчиком → статусы рейса, трекинг геопозиции/температуры (API) → рейтинг.

### Ветеринар
Профиль (лицензия, регионы) → заявки на осмотр (новые/мои) → принять с датой и ценой → отчёт с фото и заключением → прикрепляется к сделке. Проверка документов и бирок (`document:verify`).

### Сервис забоя/разделки
Объявления услуг (обряд, лицензия, выезд, виды); заявки `service_requests` (забой/разделка/упаковка, разделение на части по адресам — Курбан айт).

### Модератор
Очередь (причина попадания, автосигналы: контакты, низкая цена, дубликаты фото, массовые) → карточка → одобрить / отклонить по шаблону kk/ru с комментарием → продавец уведомлён; жалобы → решить (архивировать объявление, заблокировать пользователя); проверка документов/бирок; журнал.

### Арбитр
Список споров → переписка со сторонами (сроки ответа 48 ч) → решение: полный/частичный возврат / в пользу продавца → автоматические возврат и выплата.

### Финансовый менеджер
Сделки, выплаты (отметить выплаченным), возвраты, правила комиссий, тарифы, промокоды.

### Администратор
Всё вышеперечисленное + дашборд, пользователи и роли, справочники (регионы/категории/породы/документы/причины), карантинные зоны, CMS, баннеры, рассылки с сегментацией, настройки, аудит.

## 3. Ключевые сценарии ТЗ (как проходят в системе)

| № | Сценарий | Путь |
|---|---|---|
| 1 | Фермер (Жамбыл, слабый интернет) размещает 50 баранов с видео; 3 оффера; принимает; безопасная сделка с доставкой через биржу | `/new` (офлайн-черновик, видео) → `/profile?tab=offers` (3 оффера из сида) → принять → покупатель: сделка escrow → `/transport` заявка (ветдокументы обязательны, проверка карантина) → отклики → выбор → статусы сделки |
| 2 | Житель Астаны находит складчину на конину, бронирует ¼, оплачивает, получает мясо с казы | `/sogym` → сбор «Согым: лошадь 390 кг» → ¼ → оплата (mock) → `filled` → `distributed/completed`, предпочтение «казы» в доле |
| 3 | Мясокомбинат публикует тендер на 300 бычков из трёх областей | MVP: запрос «Куплю 300 бычков…» (`/wanted`) → продавцы категории в регионах получают уведомление → офферы; v3: `tenders`/`tender_bids` (схема готова) |
| 4 | Ресторан оформляет регулярный заказ 100 кг баранины по пятницам | MVP: запрос «Куплю» с `regular_supply`; v3: `recurring_orders` (схема готова, job генерирует сделки) |
| 5 | Администратор отмечает карантинную зону — объявления скрываются, продавцы уведомлены | `/admin/quarantine` → зона → `applyQuarantineZones()` → `hidden_quarantine` + уведомления + блок перевозок |
| 6 | Покупатель заказывает осмотр ветеринаром перед покупкой быка, получает отчёт в сделке | карточка → «Осмотр ветеринаром» → ветеринар принимает → отчёт → `/deals/:id` блок «отчёт ветеринара» |
