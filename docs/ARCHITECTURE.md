# Архитектура MalSatu

## 1. Обзор

```
┌─────────────────────────────┐     HTTPS / WSS     ┌──────────────────────────────┐
│  Web PWA (Next.js 15)       │ ◄─────────────────► │  API (Fastify 5, TypeScript) │
│  SSR + App Router, kk/ru    │                     │  /api/v1/* , /ws , /docs     │
│  Service Worker: кэш,       │                     │  модули по доменам           │
│  офлайн-черновики, push     │                     └───────┬──────────┬───────────┘
└─────────────────────────────┘                             │          │
                                                   ┌────────▼───┐  ┌───▼────────┐  ┌──────────────┐
                                                   │ PostgreSQL │  │ Redis      │  │ S3 (MinIO /  │
                                                   │ 16+PostGIS │  │ rate-limit │  │ облако в РК) │
                                                   │ pg_trgm    │  │ очереди    │  │ фото/видео   │
                                                   └────────────┘  └────────────┘  └──────────────┘
                 Внешние адаптеры (services/*): SMS · телефония (маскировка) · платежи · перевод · госсервисы · push
```

Монорепозиторий (pnpm workspaces):

- `packages/shared` — **доменное ядро без зависимостей от БД**: машина состояний сделки, комиссии, складчина, карантин, индекс цен, калькулятор выхода, антифрод, синонимы поиска, RBAC, справочники, словари. Используется и API, и web. Покрыто юнит-тестами.
- `apps/api` — HTTP/WS API. Каждый модуль: `routes.ts` (транспорт + валидация zod) → `service.ts` (бизнес-правила) → Kysely-запросы. Внешние системы — за интерфейсами в `services/*` с mock-реализациями.
- `apps/web` — экраны. Серверные компоненты для SEO-страниц (главная, карточка, лендинги «регион/категория», CMS); клиентские — для интерактива (поиск, мастер, чат, кабинеты, админка).

## 2. Обоснование ключевых решений

| Решение | Альтернатива | Почему так |
|---|---|---|
| PostGIS внутри основной БД | Elasticsearch/отдельный геосервис | один источник правды, радиус/кластеры/карантинные полигоны — обычный SQL; масштаб MVP не требует отдельного кластера |
| Полнотекст: `tsvector('simple')` + синонимы на уровне приложения + `pg_trgm` | ES с морфологией kk/ru | для казахского нет зрелого стеммера; словарь синонимов kk↔ru (`қой`=овца=баран) + префиксный поиск + триграммы для опечаток покрывают реальные запросы; легко расширять через админку |
| Kysely + ручные SQL-миграции | Prisma | Prisma плохо работает с PostGIS/tsvector/партиальными индексами; SQL-миграции прозрачны для DBA |
| Opaque session token (hash в БД) | JWT | мгновенный отзыв сессий при блокировке/удалении аккаунта; 2FA для выплат добавляется без смены схемы |
| Конструктор атрибутов в JSONB (`categories.attributes` → `listings.attributes`) | EAV-таблицы | фильтры по `attributes->>'breed'` с GIN-индексом; схема категории редактируется в админке без миграций |
| Фоновые задачи как чистые функции + runner | BullMQ сразу | в MVP достаточно; переход на BullMQ — только замена `jobs/runner.ts` |
| Server-side сеточная кластеризация карты | Leaflet.markercluster | не тащим тысячи точек на слабый мобильный интернет |

## 3. Ключевые потоки

### 3.1 Вход по телефону
`POST /auth/otp/request` → rate-limit (IP) + cooldown (номер) + чёрный список → код (HMAC-хеш в БД, TTL 5 мин, 5 попыток) → SMS-адаптер → `POST /auth/otp/verify` → создание пользователя при первом входе (`roles = buyer, seller`, уровень верификации 1) → opaque-токен сессии.

### 3.2 Публикация объявления
Мастер (web) → фото сжимаются на клиенте → черновик пишется в IndexedDB → при наличии сети `POST /media/upload` (водяной знак, превью, pHash) → `POST /listings` (идемпотентно по `clientDraftId`) → `POST /listings/:id/publish`:
1. валидация полноты (≥3 фото, цена, регион, точка; для мяса — дата и место забоя);
2. лимиты по trust-score;
3. антифрод-сигналы: контакты/ссылки в тексте, цена < 50 % медианы, дубликаты фото (pHash), массовые однотипные;
4. карантин: `evaluateListing()` по активным зонам → `hidden_quarantine`;
5. премодерация (первые 3 объявления или trust < 30 или сигналы) → `pending_moderation` + очередь; иначе `active`;
6. автоперевод недостающего языка (`auto_translated = true`, редактируемо).

### 3.3 Безопасная сделка (v2, логика реализована)
`created → paid → preparing → in_transit → inspection → confirmed → completed`, ветки `cancelled` / `disputed → refunded | partially_refunded | released_to_seller`. Переходы и допустимые роли — таблица в `shared/domain/deal.ts`; окно осмотра 24 ч (скот) / 4 ч (мясо); авто-подтверждение job'ом; выплата продавцу `amount − commission`; комиссии — правила по категории × типу аккаунта с min/max.

### 3.4 Карантинная зона
Админ создаёт зону (круг или полигон, болезнь, виды, сроки, блок перевозки) → `applyQuarantineZones()`: объявления о скоте в зоне → `hidden_quarantine` (с запоминанием прежнего статуса), остальные помечаются; заявки на перевозку из зоны → `blocked_quarantine`; продавцы получают уведомления. Job повторяет применение каждые 30 мин (зоны истекают → объявления восстанавливаются).

### 3.5 Складчина (согым)
Доли считаются в «восьмушках» (8 = туша). Бронь держится 30 мин до оплаты, затем освобождается. Все 8 оплачены → `filled` → забой/разделка/доставка. Не набрано к дедлайну → job возвращает деньги всем оплатившим.

## 4. Безопасность

- Rate-limit глобальный (300/мин на пользователя/IP) и точечный (OTP, сообщения, звонки, жалобы).
- Валидация всех входов zod; единый формат ошибок `{ error: { code } }` — тексты локализует фронт.
- RBAC: роли → права `ресурс:действие`, проверка `requirePermission()`; журнал `audit_log` для админ-действий и `moderation_log` для модераторов.
- Приватность: координаты «размываются» (≈1–2 км) для всех, кроме владельца/стаффа; телефон продавца не раскрывается — звонки через подменный номер; чёрный список по хешам номеров/реквизитов.
- Антифрод в чате: предупреждение при просьбах о предоплате/картах/ссылках (kk/ru-паттерны), фиксация сигналов в сообщении.
- Helmet, CORS по домену, bodyLimit, подписанные presigned-URL для загрузок, soft-delete и анонимизация аккаунта, экспорт данных (закон РК о ПДн; хранение — в хранилище на территории РК).
- 2FA для аккаунтов с выплатами — поле `two_factor_enabled` заложено, включается в v2 вместе с выплатами.

## 5. Масштабируемость и эксплуатация

- API без состояния (сессии в БД, сокеты — in-memory map; для нескольких инстансов — Redis pub/sub, точка замены `pushToUser`).
- Индексы: GIST по `location`, GIN по `search_vector`, `attributes`, триграммы по заголовкам, частичные индексы по статусам.
- Пики (Курбан айт, согым): кэш справочников/индекса цен (`cache-control`), SSR-страницы с `revalidate`, SW-кэш тайлов и изображений, горизонтальное масштабирование API за балансировщиком, read-replica для витрины.
- Наблюдаемость: pino-логи, `/health`, Sentry DSN, `analytics_events` (воронка просмотр → контакт → сделка), `audit_log`.
- Резервное копирование: `pg_dump`/WAL-архивация + версии бакета S3 (описано в INTEGRATIONS).

## 6. Нефункциональные требования → реализация

| Требование | Реализация |
|---|---|
| Mobile-first, слабый интернет | лёгкие страницы, lazy-img, webp-сжатие на клиенте и сервере, SW-кэш, офлайн-черновики с Background Sync |
| Простота для сельских пользователей | крупные кнопки (≥48px), иконки животных, мастер по шагам, голосовой ввод (Web Speech, kk/ru), подсказки цены и выхода мяса |
| kk/ru | словари в shared, автоперевод объявлений/сообщений с пометкой, склонения `plural()`, форматы `Intl` |
| SEO | SSR, `/{locale}/{регион}/{категория}` на двух языках, JSON-LD Product, sitemap.xml, hreflang |
| Доступность | контрастная палитра, aria-label на иконках, `prefers-reduced-motion`, семантические списки |
